# Оформление скидочной карты

Карта «Косметичка» стоит 990 ₽. Розничный клиент без скидочной карты может добавить её в корзину отдельно или с товарами. Форма запрашивает ФИО и дату рождения, телефон берётся из профиля. Пока карта в корзине, товары получают скидочную цену. Удаление карты возвращает обычный расчёт. Постоянный статус клиента покупка в корзине не меняет.

Сервер находит реальный товар по названию «Карта Косметичка» без учёта регистра. При необходимости `LOYALTY_CARD_PRODUCT_GUID` явно задаёт GUID номенклатуры. Если товар исключён из каталожного обмена, форма читает его из 1С по OData и сохраняет локально скрытым от обычного каталога. Новая номенклатура в 1С не создаётся. При отсутствии или неоднозначности товара оформление не разрешается.

Цена карты фиксирована на сервере, количество — одна, бонусы/промокоды на её стоимость не применяются. В комментарий заказа (и далее документа 1С) добавляются ФИО, дата рождения, телефон из профиля и инструкция оформить карту на кассе.

Автопривязка розничного клиента запускается сразу после успешной регистрации с подтверждением телефона по SMS, после отправки ответа клиенту. Карта ищется только в MAXMA методом `get-balance` по нормализованному телефону `+7XXXXXXXXXX`. Привязывается любой тип карты, повторное SMS не требуется. Номер телефона владельца в ответе MAXMA должен точно совпадать с телефоном аккаунта. Неоднозначные аккаунты и карты, занятые другим аккаунтом, автоматически не привязываются.

Worker раз в минуту повторяет поиск для активных одобренных розничных клиентов без карты и проверяет группу владельца уже привязанных карт в 1С. Карта остаётся той же: перенос владельца в группу «Максма Скидка» включает скидочные цены, выход из группы возвращает обычный статус. Номер карты и префикс 900 не определяют скидку. Привязанные вручную карты автоматически не заменяются.

Сбой MAXMA не отменяет регистрацию; поиск повторяется в фоне. Карта сохраняется до проверки группы в 1С: сбой 1С не мешает привязке, но скидка не назначается без подтверждения. Для уже привязанной карты сбой 1С сохраняет прежний статус. Открытый профиль обновляет карту каждые 30 секунд, данные клиента — раз в минуту в активном приложении; задержка зависит от ответа внешних сервисов.

Схема базы не меняется. Выкладка: сначала backend `kosmetichka-b2b`, затем `kosmetichka-app`. Проверки API не оформляют реальные карты в 1С и не создают заказы на рабочем сервере.
